Ты разрабатываешь Linux-дистрибутив **Exedra**.

Сейчас нужно реализовать отдельную базовую редакцию:

# Exedra Core

Это минимальная, но полностью пригодная для установки и обслуживания система. Она должна быть основой для других редакций Exedra.

## Главное

* Название дистрибутива: **Exedra**
* Пакетный менеджер: **venim**
* Core не должен зависеть от Desktop Edition.
* Не создавать отдельную Rescue Edition.
* Все необходимые инструменты восстановления и диагностики должны находиться непосредственно в Core.
* Система должна работать как полноценный **Live CD / Live ISO**.
* Архитектура должна позволять в дальнейшем использовать Core как основу для устанавливаемой системы.

## Что должно входить в Core

### Базовая система

Включить только действительно необходимые компоненты:

* kernel
* init/system initialization
* system utilities
* shell
* core GNU/Linux utilities
* networking
* hardware detection
* storage management
* filesystem support
* users/groups management
* permissions
* process management
* logging
* service management
* package management через `venim`

Не добавлять полноценное графическое окружение.

## Пакетный менеджер

`venim` является нативным пакетным менеджером Exedra.

Он должен быть установлен и полностью доступен из Core.

Все операции установки, удаления, обновления и поиска пакетов должны проходить через `venim`.

Не заменять `venim` сторонним пакетным менеджером и не использовать другое название.

## Сетевые инструменты

Предусмотреть инструменты для:

* диагностики сети
* настройки Ethernet
* настройки Wi-Fi
* DNS
* маршрутизации
* проверки соединения
* загрузки пакетов
* диагностики сетевых проблем

## Storage / Recovery

Так как отдельной Rescue Edition больше нет, Core должен содержать необходимые инструменты для обслуживания сломанной системы.

Предусмотреть:

* просмотр дисков и разделов
* создание/изменение разделов
* форматирование
* mounting/unmounting
* проверку файловых систем
* восстановление файловых систем
* работу с UUID/LABEL
* работу со swap
* диагностику дисков
* работу с LVM, если она поддерживается базовой архитектурой
* работу с RAID, если она поддерживается базовой архитектурой
* работу с encrypted volumes, если они поддерживаются
* инструменты для chroot
* восстановление установленной системы
* работу с bootloader
* диагностику загрузки
* просмотр системных логов

Не создавать отдельные rescue-сценарии или отдельный интерфейс Rescue Edition. Просто предоставить необходимые инструменты в Core.

## Диагностика

Добавить консольные инструменты для диагностики:

* CPU
* RAM
* GPU
* PCI
* USB
* disks
* network
* kernel
* system services
* boot
* filesystem

## Live Environment

Core ISO должна загружаться непосредственно с USB/DVD/ISO.

После загрузки пользователь должен получить рабочую консольную среду.

Live-система должна:

1. корректно определить оборудование;
2. поднять сеть;
3. запустить `venim`;
4. предоставить инструменты диагностики;
5. позволить смонтировать установленную систему;
6. позволить выполнить chroot;
7. позволить исправить установленную систему;
8. позволить установить Exedra на диск в будущем.

## Архитектура

Организуй проект модульно.

Отдельно:

* base system
* kernel
* package manager
* networking
* storage
* filesystem tools
* recovery tools
* hardware tools
* live environment
* ISO generation

Не смешивать Core с Desktop-компонентами.

## Что НЕ нужно

Не добавлять:

* KDE Plasma
* GNOME
* XFCE
* полноценный Desktop Environment
* офисные приложения
* браузеры без необходимости
* мультимедиа-программы
* игры
* пользовательские графические приложения
* лишние фоновые сервисы
* дублирующие инструменты

Core должен оставаться компактным.

## Результат

Собери полноценную **Exedra Core Live ISO**.

Она должна быть:

* минимальной;
* стабильной;
* пригодной для установки;
* пригодной для диагностики;
* пригодной для восстановления;
* пригодной как основа для Desktop Edition;
* полностью использующей `venim`.

Не делай временный mockup. Реализуй архитектуру так, чтобы проект можно было дальше развивать в полноценный Linux-дистрибутив.
