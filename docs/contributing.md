# Contributing

- Один рецепт = один файл `packages/<name>/<version>/<name>.vnb`.
- `source_sha256` / `binary_sha256` обязателен. Без хэша PR не принимается.
- Источники только официальные: upstream-релиз, зеркало дистрибутива. Архивы с файлообменников — отказ.
- Патчи рядом с рецептом в `files/`, по одному файлу на изменение.
- Перед PR: `venim build` проходит, `venim verify` чисто, `./tests/run.sh` зелёный.
- Не копировать файлы в `/usr` в рецептах — только `${destdir}`.
- Meta-пакеты (DE/WM) — только `depends`, без функций сборки.

## Как оформить PR

- ветка от main, один PR — один пакет или одно исправление;
- имя коммита: `pkg: <name> <version>`;
- в описании: откуда взят source/binary, как проверен.

## Стиль рецепта

- порядок полей как в примере nano (см. `docs/venimbuild.md`);
- depends по алфавиту, без дублей;
- версии фиксированные, без `latest`.

## Что отклоняется

- архивы без sha256;
- неофициальные источники;
- запись в `/`, `/usr` мимо `${destdir}`;
- бинарники, залитые прямо в репо вместо URL.

Вопросы — в issues, с логом `venim build --verbose` и хэшем архива.
