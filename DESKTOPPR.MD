Ты разрабатываешь Linux-дистрибутив **Exedra**.

Нужно создать отдельную редакцию:

# Exedra Desktop

Desktop Edition должна строиться **поверх Exedra Core**, а не быть отдельным независимым дистрибутивом.

Пакетный менеджер системы — **venim**.

## Основная концепция

Exedra Desktop должна быть готовой системой для обычного пользователя после загрузки Live ISO и последующей установки.

В ней должны быть:

* полноценное графическое окружение;
* графический вход;
* файловый менеджер;
* браузер;
* офисный пакет;
* мультимедиа;
* системные настройки;
* графические системные инструменты;
* базовые пользовательские приложения.

## Desktop Environment

Использовать **KDE Plasma** как основное графическое окружение.

Настроить:

* Plasma
* KDE Frameworks
* KDE Gear
* Wayland
* SDDM
* PipeWire
* NetworkManager
* Bluetooth
* printer support
* audio
* графическую поддержку
* уведомления
* управление питанием
* system settings

Система должна запускаться сразу в полноценный графический интерфейс.

## Основные приложения

В базовый образ включить:

### Интернет

* Chromium или другой выбранный основной браузер

### Офис

* LibreOffice

### Файлы

* Dolphin

### Архивы

* KDE Ark

### Текст

* простой текстовый редактор KDE

### Терминал

* KDE Konsole

### Системные приложения

* KDE System Settings
* системный монитор
* управление дисками
* сетевые настройки
* управление пользователями
* управление Bluetooth
* управление принтерами

## Мультимедиа

Предусмотреть полноценную поддержку:

* PipeWire
* PulseAudio compatibility
* ALSA
* видео
* аудио
* кодеков, необходимых для обычного использования

Не устанавливать десятки ненужных мультимедийных приложений.

## Hardware

Desktop Edition должна автоматически определять и использовать оборудование пользователя.

Предусмотреть:

* Intel GPU
* AMD GPU
* NVIDIA GPU
* Wi-Fi
* Bluetooth
* audio devices
* webcams
* USB devices
* printers
* touchpads
* external monitors

Драйверная архитектура должна быть модульной.

## NVIDIA

Предусмотреть нормальную поддержку NVIDIA, включая возможность использовать проприетарный драйвер там, где это необходимо.

Не ломать систему при отсутствии NVIDIA GPU.

## Системные инструменты Core

Все возможности Exedra Core должны оставаться доступны в Desktop Edition.

То есть Desktop должна содержать:

* `venim`
* storage tools
* filesystem tools
* network diagnostics
* hardware diagnostics
* boot/recovery tools
* chroot tools
* system diagnostics

Не создавать отдельную Rescue Edition.

Если пользователь открыл терминал, он должен иметь доступ ко всем инструментам Core.

## Графические инструменты

По возможности предоставить GUI для наиболее частых операций:

* управление дисками
* сетевые настройки
* пользователи
* пакеты
* системные обновления
* настройки загрузки
* оборудование

При этом CLI-инструменты Core должны оставаться основным низкоуровневым способом администрирования.

## Live ISO

Exedra Desktop должна собираться как полноценная Live ISO.

После загрузки:

1. запускается KDE Plasma;
2. определяется оборудование;
3. работает сеть;
4. работают звук и Bluetooth;
5. доступны базовые приложения;
6. доступен `venim`;
7. доступны инструменты Core;
8. пользователь может протестировать систему;
9. пользователь может запустить установку на диск.

## Installer

Предусмотреть отдельный современный графический установщик.

Он должен поддерживать как минимум:

* выбор диска;
* разметку;
* автоматическую разметку;
* файловую систему;
* swap;
* пользователя;
* hostname;
* часовой пояс;
* раскладку клавиатуры;
* установку bootloader;
* установку пакетов;
* создание загрузочной системы;
* завершение установки.

Установщик должен устанавливать именно Exedra, а не превращать систему в другую Linux-систему.

## Внешний вид

Создать единый визуальный стиль Exedra.

Название:

**Exedra**

Не использовать названия старых вариантов проекта вроде NexaCore в интерфейсе, ISO metadata, package metadata или branding.

Интерфейс должен выглядеть как законченный дистрибутив, а не как обычная KDE Plasma установка с несколькими изменёнными настройками.

## Архитектура

Структура должна быть примерно такой:

```text
Exedra
├── Core
│   ├── base
│   ├── kernel
│   ├── venim
│   ├── networking
│   ├── storage
│   ├── recovery
│   └── live
│
└── Desktop
    ├── Core
    ├── KDE Plasma
    ├── SDDM
    ├── applications
    ├── multimedia
    ├── drivers
    ├── installer
    └── branding
```

Desktop не должна дублировать Core.

Если пакет или компонент уже предоставляется Core, Desktop должен использовать его.

## Главное требование

Сделай две логически связанные редакции:

**Exedra Core**
→ минимальная консольная система + все системные/recovery-инструменты.

**Exedra Desktop**
→ Exedra Core + KDE Plasma + GUI + приложения + installer.

Обе редакции должны использовать один фундамент, один пакетный менеджер `venim` и общую архитектуру.

Не превращай проект в набор несвязанных скриптов. Реализуй нормальную структуру дистрибутива, которую можно будет дальше расширять.
